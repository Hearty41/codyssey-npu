# Mini NPU Simulator (E1-3)

AI(인공지능)의 핵심 연산인 **MAC(Multiply-Accumulate)** 원리를 파이썬 표준 라이브러리만으로 구현한 콘솔 시뮬레이터입니다.  
외부 수치 연산 라이브러리(NumPy 등) 없이 2차원 배열 순회로 패턴 유사도를 계산하고, 부동소수점 오차 방어 정책과 입력 크기(N)에 따른 시간 복잡도(O(N²))를 검증합니다.

---

## 1. 실행 방법

1. `main.py`와 `data.json` 파일이 같은 폴더에 있는지 확인합니다.
2. 터미널(PowerShell)에서 아래 명령어로 프로그램을 실행합니다.
   ```bash
   python main.py
   ```
3. 메뉴 번호를 입력해 원하는 모드를 실행합니다.
   - **`1` (사용자 입력 3×3)**: 3×3 필터 A, B와 3×3 패턴을 한 줄씩(공백 구분) 직접 입력하여 MAC 점수, 판정 결과, 연산 시간을 확인합니다.
   - **`2` (data.json 분석)**: `data.json`에 정의된 `5×5`, `13×13`, `25×25` 필터와 패턴을 일괄 분석하여 PASS/FAIL 여부, 크기별 평균 연산 시간 표, 전체 요약 리포트를 출력합니다.
   - **`0` (종료)**: 시뮬레이터를 종료합니다.

---

## 2. 구현 요약

- **라벨 정규화 (`normalize_label`)**: `data.json` 내부에서 혼용되는 필터 키(`cross`, `x`)와 정답 기호(`+`, `x`)를 프로그램 내부 표준 라벨인 **Cross**와 **X** 두 가지로 통일하여 일관된 비교가 가능하도록 구현했습니다.
- **MAC 연산 (`mac_operation`)**: 외부 라이브러리 없이 이중 `for`문으로 입력 패턴과 필터의 동일 위치 원소를 곱한 뒤 누적 합산(`total_score += pattern[r][c] * filter_matrix[r][c]`)하여 `float` 점수를 반환합니다.
- **허용오차 기반 판정 (`judge_scores`)**: 부동소수점 연산 오차를 보정하기 위해 `abs(score_a - score_b) < 1e-9` 조건을 적용했으며, 두 점수의 차이가 `1e-9` 미만일 경우 동점(`UNDECIDED`)으로 판정합니다.
- **데이터 검증 및 예외 처리**: 모드 1에서는 행·열 개수 불일치 및 숫자 파싱 오류 시 안내 문구 출력 후 재입력을 유도하며, 모드 2에서는 패턴 키와 실제 배열 크기(N × N) 불일치 시 프로그램이 중단되지 않고 해당 케이스만 `FAIL`로 기록한 뒤 다음 테스트를 이어갑니다.

---

## 3. 결과 리포트

### 3-1. 테스트 요약 및 실패(FAIL) 원인 분석
`data.json`의 총 6개 테스트 케이스를 실행한 결과 **통과(PASS) 3개**, **실패(FAIL) 3개**가 발생했습니다.

- **PASS 케이스 (3개)**: `size_5_2`, `size_13_1`, `size_25_2`
- **FAIL 케이스 (3개)**:
  1. **`size_5_1`**: Cross 점수 `0.9000000000000000`, X 점수 `0.8999999999999999` → 판정 `UNDECIDED` (expected: `X`)
  2. **`size_13_2`**: Cross 점수 `7.4999999999999973`, X 점수 `7.5000000000000000` → 판정 `UNDECIDED` (expected: `Cross`)
  3. **`size_25_1`**: Cross 점수 `4.9000000000000004`, X 점수 `4.8999999999999986` → 판정 `UNDECIDED` (expected: `X`)

**원인 진단 (수치 비교 정책 및 부동소수점 오차 분석)**  
- 위 3건의 실패는 데이터 스키마 오류나 반복문 로직 오류가 아니라, **수학적으로 동점인 데이터와 IEEE 754 부동소수점 표현 오차** 때문에 발생했습니다.
- 예를 들어 `size_13_2`의 경우 수학적 이론값은 Cross(`0.3 × 25 = 7.5`)와 X(`7.5 × 1.0 = 7.5`)가 완전히 동일하지만, 컴퓨터가 2진수로 실수 `0.3`을 25번 누적 합산하는 과정에서 `7.4999999999999973`이라는 미세한 오차(약 2.7 × 10⁻¹⁵)가 발생합니다.
- 만약 허용오차(`epsilon = 1e-9`) 없이 단순 대소 비교(`score_a > score_b`)만 수행했다면, 실제 패턴 모양과 무관하게 부동소수점 반올림 오차 방향에 따라 우연히 승패가 갈리는 왜곡된 판정이 내려졌을 것입니다.
- 따라서 본 시뮬레이터는 `1e-9` 이내의 미세 차이를 실질적 동점(`UNDECIDED`)으로 엄격하게 걸러냈으며, 그 결과 단일 정답(`Cross` 또는 `X`)을 요구하는 `expected` 기준과 불일치하여 정상적으로 `FAIL` 처리되었습니다.

### 3-2. 성능 측정 결과 및 시간 복잡도 O(N²) 분석
입출력(I/O) 시간을 제외하고 순수 MAC 연산 함수(`mac_operation`)만 크기별 10회 반복 측정한 평균 결과는 다음과 같습니다.

| 패턴 크기 (N × N) | 평균 연산 시간 (ms) | 총 MAC 연산 횟수 (N²) |
| :---: | :---: | :---: |
| **3×3** | 0.0006 ms | 9회 |
| **5×5** | 0.0010 ms | 25회 |
| **13×13** | 0.0054 ms | 169회 |
| **25×25** | 0.0198 ms | 625회 |

**시간 복잡도 근거**  
- MAC 연산은 가로 길이 N, 세로 길이 N인 2차원 배열의 모든 원소를 한 번씩 방문하여 곱셈과 덧셈을 수행하는 이중 반복문 구조이므로, 전체 연산 횟수는 정확히 N × N = N²에 비례합니다.
- 실제 측정 데이터에서도 패턴 크기가 `3×3`(9회)에서 `25×25`(625회)로 커질 때 연산 횟수는 약 **69.4배** 증가하며, 평균 연산 시간 역시 `0.0006 ms`에서 `0.0198 ms`로 **33배** 가파르게 증가하는 양상을 보입니다.
- 입력 크기 N이 커질수록 실행 시간이 제곱(N²)에 비례해 증가하므로, 본 알고리즘의 시간 복잡도는 **O(N²)**임을 실험적으로 확인할 수 있습니다.
